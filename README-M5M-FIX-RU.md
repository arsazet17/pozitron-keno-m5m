# M5M: точечное исправление чтения Stoloto

Оверлей подготовлен для репозитория `arsazet17/pozitron-keno-m5m` по состоянию ветки `main` на 7 сентября 2026 года.

## Перед заменой

Проверьте, что исходные файлы ещё не изменились:

```bash
git hash-object scripts/m5m_stoloto_sync.py
# beb53e39233f90ec080f2383994791732f3f1630

git hash-object .github/workflows/m5m-auto.yml
# d716a6acdcc5cf7465925c3b302a93d697b561bf
```

Если SHA отличаются, не заменяйте файлы вслепую: сначала сравните изменения.

## Установка

Распакуйте ZIP в корень репозитория с заменой двух файлов:

- `scripts/m5m_stoloto_sync.py`
- `.github/workflows/m5m-auto.yml`

`README-M5M-FIX-RU.md` служит только инструкцией; коммитить его не обязательно.

## Что исправлено

1. Целевой тираж фиксируется в начале запуска и больше не сдвигается во время установки Chromium и повторных чтений. Использована семиминутная задержка публикации, чтобы не требовать результат тиража в минуту его старта.
2. Хвост принимается по непрерывному совпадению `2 из 3`: десять строк в обычном случае или девять при нормальном сдвиге хвоста на один тираж. Каждая принятая строка всё равно должна совпасть минимум в двух чтениях.
3. OAuth-форма ожидается до 15 секунд и ищется только среди видимых полей, включая iframe. Если форма не появилась, workflow прикладывает безопасную диагностику без значений полей и без секретов.
4. Расписание не включено: workflow по-прежнему запускается только через `workflow_dispatch`.

## Проверка после коммита

Запустите `M5M · Stoloto AUTO` вручную один раз. В журнале должны появиться строки `Frozen M5M target` и `Stable tail consensus`. Если OAuth снова не откроется, скачайте артефакт `m5m-oauth-diagnostics-*`; он хранится три дня.
